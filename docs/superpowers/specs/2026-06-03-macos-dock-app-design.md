# macOS Dock launcher app — design

**Date:** 2026-06-03
**Status:** Approved, pre-implementation
**Target version:** 1.9.0

## Problem

There's no clickable way to open the explorer. Users launch it via
`/session-explorer:open` inside Claude Code, or by running
`session-explorer launch` in a terminal. A user who wants a Dock icon has to
hand-roll an Automator app — and that path is full of traps we hit firsthand:

1. **PATH.** Automator's *Run Shell Script* runs with a stripped PATH that
   excludes `/opt/homebrew/bin`, so `shutil.which("tmux")` (in `tmux.available()`,
   `bin/_pkg/tmux.py`) returns `None` and `launch` silently falls back to the
   non-tmux `execvp` path. The app opens *without* tmux even though tmux is
   installed.
2. **Icon override.** Automator applets ship a compiled `Assets.car` and an
   `Info.plist` carrying **both** `CFBundleIconFile` *and* `CFBundleIconName`.
   Modern macOS (LaunchServices) prefers `CFBundleIconName` → `Assets.car` and
   ignores a replaced loose `.icns`, so the custom icon never shows until the
   `CFBundleIconName` key is removed and the app re-signed.

We want a first-class, documented one-command install that produces a Dock app
with the right icon that launches *with* tmux — reachable by both the
marketplace and plain-install users.

## Key facts

- **Two install paths, one must-reach surface.** Marketplace users never run
  `install.sh`; their binary lives at
  `~/.claude/plugins/cache/session-explorer/session-explorer/<version>/bin/session-explorer`
  (the version segment changes on update). Plain-install users get a
  `~/.local/bin/session-explorer` symlink. A feature that only lives in
  `install.sh` would miss the recommended (marketplace) path.
- **A `.app` is just a directory.** `Contents/MacOS/<exe>` + `Contents/Info.plist`
  + `Contents/Resources/icon.icns`. No Automator, no Xcode, no `actool` needed.
- **A shell-script app needs no code-signing.** There's no Mach-O to validate,
  and a locally created bundle carries no `com.apple.quarantine` xattr, so
  Gatekeeper does not block it.
- **`sips` and `iconutil` are always present on macOS** — but we don't need them
  at install time because we ship a prebuilt `.icns`.

## Design

### 1. New CLI subcommand: `install-app`

`session-explorer install-app` (added to `bin/_pkg/cli.py` alongside
`launch`/`index`/`live`/`uninstall`/`list`). Because it ships with the binary,
it is reachable from **both** install paths.

- **macOS-only.** On non-Darwin platforms it prints a one-line notice and
  returns a non-zero exit; it does nothing.
- **Idempotent.** If the target app already exists it is removed and recreated,
  the icon cache is refreshed, and the Dock pin is reconciled (no duplicate
  entry).
- **Flags** (also the testability seam):
  - `--dest <dir>` — parent dir for the app (default `~/Applications`).
  - `--no-dock` — create the app but skip Dock pinning.
  - `--name <str>` — app display name (default `Session Explorer`).

Implementation lives in a new module `bin/_pkg/macapp.py` so `cli.py` stays a
thin dispatcher and the logic is unit-testable in isolation.

### 2. The generated bundle (hand-built)

```
<dest>/Session Explorer.app/Contents/
├── Info.plist                     # authored by us — see below
├── MacOS/session-explorer-launch  # generated zsh script, chmod 0755
└── Resources/icon.icns            # copied from assets/app-icon.icns
```

**`Info.plist`** (minimal, plist-XML) — deliberately carries `CFBundleIconFile`
and **no** `CFBundleIconName`, sidestepping the Automator icon-override trap:

| Key | Value |
|-----|-------|
| `CFBundleName` | `Session Explorer` (from `--name`) |
| `CFBundleDisplayName` | same |
| `CFBundleIdentifier` | `com.snojken.session-explorer.dock` |
| `CFBundleExecutable` | `session-explorer-launch` |
| `CFBundleIconFile` | `icon` (→ `Resources/icon.icns`) |
| `CFBundlePackageType` | `APPL` |
| `CFBundleVersion` / `CFBundleShortVersionString` | the plugin version |
| `LSMinimumSystemVersion` | `10.15` |
| `NSHighResolutionCapable` | `true` |
| `LSBackgroundOnly` | `false` |

**`MacOS/session-explorer-launch`** — the crux. A generated zsh script that
(a) repairs PATH so tmux is discoverable in the GUI launch context, (b) resolves
the binary in a way that survives plugin version bumps, and (c) execs `launch`:

```sh
#!/bin/zsh
# Generated by `session-explorer install-app`. Do not edit by hand.
export PATH="/opt/homebrew/bin:/usr/local/bin:$PATH"

# Resolve the session-explorer binary. Marketplace installs live under a
# versioned cache path that changes on update, so resolve at run time rather
# than baking an absolute path.
CLI="$(/usr/bin/python3 - <<'PY' 2>/dev/null
import json, os
f = os.path.expanduser("~/.claude/plugins/installed_plugins.json")
try:
    d = json.load(open(f))
except Exception:
    d = {}
e = d.get("plugins", {}).get("session-explorer@session-explorer", [])
p = (e[0].get("installPath", "") + "/bin/session-explorer") if e else ""
print(p if os.path.exists(p) else "")
PY
)"
[ -x "$CLI" ] || CLI="$(command -v session-explorer)"
[ -x "$CLI" ] || CLI="$HOME/.local/bin/session-explorer"
exec "$CLI" launch
```

The resolver mirrors the strategy already used in the README's marketplace
uninstall one-liner. `launch` itself is unchanged — it already does the
tmux-vs-fallback decision; we are only ensuring tmux is *findable* when it runs.

### 3. Icon asset

A new top-level `assets/` directory holds the committed art:

- `assets/app-icon.icns` — prebuilt, what `install-app` copies into the bundle.
- `assets/app-icon.png` — 1024×1024 master (source of truth for the `.icns`).
- `assets/app-icon.svg` — editable source for future tweaks.

`install-app` simply copies `app-icon.icns`. No render/build step at install
time. The PNG/SVG are kept so the icon can be regenerated
(`sips`/`iconutil`) when edited; that regeneration is a manual maintainer step,
not part of `install-app`.

### 4. Dock pinning (best-effort)

After the bundle is written:

1. `touch` the app, run LaunchServices `lsregister -f <app>`, and remove the
   user `iconservices.store` cache, then `killall Dock` — so the new icon shows
   immediately. (These are the steps that fixed the icon during manual testing.)
2. Unless `--no-dock`: pin to the Dock, but only if not already pinned. Read the
   current `com.apple.dock` `persistent-apps` array; if no entry already points
   at this app path, append one via
   `defaults write com.apple.dock persistent-apps -array-add '<dict>'` and
   `killall Dock`.
3. **Every Dock step is best-effort.** Any failure (sandboxed defaults, unusual
   setup) is caught and downgraded to a printed instruction:
   *"Created ~/Applications/Session Explorer.app — drag it to your Dock to pin
   it."* The subcommand still returns success because the app itself was built.

### 5. Teardown

Fold into the existing `uninstall` (`bin/_pkg/uninstall.py` `teardown()`), as a
new best-effort step: if `~/Applications/Session Explorer.app` (and the
`--dest` default) exists, remove it and remove its `persistent-apps` Dock entry,
then `killall Dock`. No-op when absent. No new uninstall surface. macOS-guarded
so the step is skipped on Linux/CI.

## Testing

A bats test (`test/macapp.bats`, gated to run only on macOS via
`$OSTYPE`/`uname`) exercises the build without touching the real
`~/Applications` or Dock:

```
session-explorer install-app --dest "$TMP" --no-dock
```

Assertions:

- `"$TMP/Session Explorer.app/Contents/MacOS/session-explorer-launch"` exists and
  is executable.
- The launcher script contains the `export PATH="/opt/homebrew/bin:...` line and
  the resolver fallback to `~/.local/bin/session-explorer`.
- `Info.plist` contains `CFBundleIconFile` and does **not** contain
  `CFBundleIconName` (the regression guard for the Automator trap).
- `Resources/icon.icns` exists and is a valid `icns`
  (`sips -g format` reports `icns`).
- Re-running the command leaves exactly one app (idempotency).

Pure-logic helpers in `macapp.py` (plist string builder, launcher-script
builder, "is this app already pinned?" predicate over a sample plist) get
`pytest` unit coverage in `test/test_macapp.py` so the bulk of the logic is
covered cross-platform; the bats test covers the real filesystem build on macOS
only.

## Out of scope

- Linux/Windows desktop entries (the launcher already covers terminal spawning
  there; a `.desktop` file is a separate future request).
- Code-signing / notarization (unnecessary for a locally built script app).
- Auto-regenerating the `.icns` from the PNG during `install-app`.
